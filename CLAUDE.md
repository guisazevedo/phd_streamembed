# CLAUDE.md

PhD research code on the BRACS breast-pathology data set (547 whole-slide images, 7 classes): slides -> tile embeddings with UNI2-h, saved as one `.pt` file per slide, for a later classifier. See `README.md` for the overview, the data set facts, the output format and the pipeline diagrams.

## Commands

```bash
uv sync                                   # install dependencies (Python >= 3.14, uv.lock)
uv run jupyter lab                        # run the notebooks
uv run python setup_only/model_download.py   # fetch UNI2-h weights into original_vit_model/
```

There is no test suite and no linter configured. Verify changes by running the code on real or synthetic data (the label sheet and the slides in `data/` exist locally; feature files may not). When writing throwaway scripts, put them in the session scratchpad, not in the repo. Run Python from the repository root (`utils` is imported as a top-level package; `.venv/bin/python` works without `uv run`).

## Notebooks

Numbered, in order. Keep each one thin (logic belongs in `utils/`), with a markdown cell before every code cell and the figure explanation in the figure captions.

- `00_data_visualization.ipynb`: the data set. Labels and class definitions, audit of the official split, RoI composition, class weights, slide properties, pyramid levels, tile examples. Writes `slides.csv` and `class_weights.csv` to `outputs/00_data_overview/`.
- `01_1_wsi_to_vectors.ipynb`: tiling -> UNI2-h embeddings -> inspection (one file, all slides, choice of k, embeddings vs the 7 classes).
- `01_2_vectors_to_pca_analysis.ipynb`: PCA of the saved CLS embeddings (`utils/pca_analysis.py`). One PCA fitted on a slide-balanced tile sample of official Training slides (`sample_tiles`, `fit_pca`, randomized or incremental, never whitened), evaluated on Validation slides of patients not in Training (`split_fit_eval`); explained variance, spectrum and effective rank (truncated flag and bounds), reconstruction (MSE, NMSE, cosine), cosine neighbour preservation by exact torch top-k (Recall@10/20, Spearman; faiss is not installed), `final_comparison` and `recommend_dimensions`. Writes `pca_<d>/UNI2-h/<slide>.pt`, `pca_model.pt` and `metadata.json` under `/mnt/Scratch/phd_streamembed_features/` (`save_pca_embeddings` refuses to overwrite unless `OVERWRITE`; Testing slides are only transformed). No figures or reports are exported. Note that 01_3's own text and 02_3 still call the synthetic-slide notebook "01_2".
- `01_3_pca_to_synthetic_vectors.ipynb`: synthetic WSI bags from the PCA vectors of 01_2 (`utils/synthetic_gaussian.py`; not the same as `01_3_wsi_to_mod_vectors.ipynb`, which resamples real tiles). Training slides only (`load_training_slides` validates dimension, label, set and the `fit_slides` of 01_2). Per PCA dimension and class, `MiniBatchKMeans` for every k, then one streaming pass (`collect_class_statistics`) gives the per-slide cluster composition (templates) and the Gaussian sums; `GaussianGenerator` (diag default, full optional, `COVARIANCE_REG`, pooled variance for clusters below `MIN_CLUSTER_TILES`) behind `GeneratorBase`/`GENERATORS`; `make_synthetic_wsi` blends `N_TEMPLATES_PER_WSI` real Training templates with Dirichlet weights (`TEMPLATE_CONCENTRATION`; 1 = one slide) so no bag follows one slide's size or composition; no template ids are stored (`n_templates`, `max_template_weight` only); no formal privacy claim. Output `<SYNTHETIC_OUTPUT_DIR>/<method>/pca_<D>/k_<K>/` (float32, keys of the PCA files, `set='Synthetic'`) with `metadata.json`, `cluster_models.pt`, `labels.csv`, and `labels/BRACS_synthetic.csv`; refuses to overwrite unless `OVERWRITE`. Diagnostics only (no classifier). Input root spelled `phd_streamembed_features`.
- `01_3_wsi_to_mod_vectors.ipynb`: synthetic slides from the saved real vectors (`utils/synthetic_slides.py`: `make_synthetic_folds`, `save_synthetic_folds`, `write_mod_labels`). Per CV fold (same `N_FOLDS`, `EARLY_STOP_FRACTION`, `SEED` as 02_3), `N_TOTAL` slides from that fold's fit / early-stopping slides only, written to `/mnt/Scratch/phd_streamembed_features/level_1_mod/UNI2-h/fold_<k>/` (recipes cached in `level_1_mod/recipes/`) and listed in `labels/BRACS_mod.csv` (CSV, not xlsx: no xlsx writer, no new package; columns of BRACS.xlsx plus `fold`, `part`, `size`, `n_sources`, `max_share`, `sources`). Final check reloads one slide per fold against the real bags.
- `02_0_vectors_to_classifier_selector.ipynb`: multiple-instance classifier (gated ABMIL and CLAM-MB, shown side by side; `MODELS` and `MODEL_ARGS` in section 2; the mean-pool linear baseline stays in `mil_models.py` and can be added to `MODELS`) on the saved CLS embeddings; official Testing set unchanged and evaluated once, every choice made by patient-grouped cross-validation over Training + Validation (`utils/mil_cv.py`, nested early stopping), final models = the fold models of the selected setting; full metrics with patient-bootstrap intervals; results are only shown on screen; the one file it writes is the best classifier (chosen on the early-stopping macro-F1 of the fold models, never on Testing) to `classifier/classifier_model_<date-time>.pt`.
- `02_1_vector_to_classifier_experimentation.ipynb`: one CLAM-MB per label set (Benign/Atypical/Malignant, Non-cancer/Cancer, Non-cancer/DCIS/IC, mappings in `LABEL_SETS`), trained on Training + Validation with one patient-grouped early-stopping split (`utils/final_classifier.py`), settings fixed as constants from notebook 02 (no search), evaluated once on the official Testing set (confusion matrix, ROC/AUROC, accuracy, F1, sensitivity, specificity, precision, patient-bootstrap intervals); writes one classifier per label set to `classifier/final/<label set>/`. The coarse auxiliary loss, `cv_compare` and `clinical_views` are 7-class only and are not used there. Sections 7-9 add a two-stage variant of the 3-class problem (the Cancer model, then a DCIS/IC CLAM-MB trained on cancer slides only; `make_stage2_table`, `cascade_predict`: the first stage alone decides Non-cancer, measures from the cascade confusion matrix, AUROC from the chain-rule scores of `combine_two_stage`), compared with the flat model by `paired_bootstrap_views`. Every 02_1 model trains with the class-weighted loss and selects the epoch on macro-F1 with the class-weighted early-stopping loss as tie-break (`train_model(weighted_val_loss=True)`; the default stays unweighted for notebook 02).
- `02_2_vector_to_classifier_finetunning.ipynb`: tuning of the direct 3-class model (Non-cancer / Non-invasive atypia-neoplasia = ADH+DCIS / Invasive carcinoma, `THREE_MAPPING`): optuna TPE (`utils/mil_tuning.py`) over `lr`, `weight_decay`, `dropout`, `coarse_weight`, `k_sample` and `max_tiles` (2048, 4096, 8192, None; `batch_size_for` scales the batch with the cap); 20 trials, each a 5-fold `mil_cv.cross_validate` scored by the pooled out-of-fold macro-F1; `select_setting` (recall floor `MIN_CLASS_RECALL` as a float, a dict or None; `eligible_trials` reports the best achievable recall when no trial passes; one-standard-error rule), confirmation of the top 2 with 2 repeats and new seeds, ensemble = fold models of the chosen setting (5 x 2 = 10 models, `save_ensemble`, one file), Testing used once, paired comparison with the 3-class model of 02_1 section 10 (`classifier/final/noncancer_adhdcis_ic/`). The coarse loss uses `train_model(tiers=TIERS_3)` (Non-cancer vs lesion); `cv_compare` is 7-class only and is not used. The study `three_class` lives in `outputs/02_2_tuning/study.db` (resumable; delete it or change `STUDY_NAME` to start over). The earlier 4-class version, with its ADH results (ADH never predicted on Testing), is `02_2_vector_to_classifier_finetunning_4class.ipynb` (study `adh_four_class`).
- `02_3_pca_vector_to_classifier_finetunning.ipynb`: the process of 02_2 (same search incl. `max_tiles`, selection, confirmation, ensemble, Testing used once) on the **PCA-reduced real vectors** of 01_2. The constant `DIMENSION` (default 512; 256, 1024, ... possible) selects `<FEATURES_ROOT>/pca_<DIMENSION>/UNI2-h/` (`FEATURES_DIR`; `load_bags` reads it unchanged and the notebook asserts `data['dim'] == DIMENSION`); the study is `three_class_pca<DIMENSION>` in `outputs/02_3_tuning/study.db`, the trials table `trials_<study>.csv`, the ensemble `classifier/final/noncancer_noninvasive_invasive_pca<DIMENSION>/`. The PCA was fitted on Training tiles only (01_2), so Testing stays untouched. Sections 8.3 / 8.4 compare with the 02_1 model and the 02_2 ensemble, which are 1536-d, so the original vectors of the Testing slides are read from `FEATURES_FULL_DIR` (`level_1/`; `data_full3`) and the paired bootstrap is PCA minus 1536-d. It does not use synthetic slides: `01_3_wsi_to_mod_vectors.ipynb` and `utils/synthetic_slides.py` are kept but no notebook consumes them now (the optional `train_table` / `bags` keys of `mil_cv.fold_data` are used by 02_4 with the synthetic bags of 01_3_pca) (the earlier synthetic version of this notebook was `02_3_mod_vector_to_classifier_finetunning.ipynb`).
- `02_4_synthetic_vector_to_classifier_finetunning.ipynb`: the process of 02_3 (same folds, search, selection, confirmation, ensemble, Testing used once) with the classifier **fitted on the synthetic bags of 01_3** (`utils/synthetic_training.py`). Per fold, `training_folds` sets `train_table` = all synthetic slides of the sampled k (role Training, three-class labels from `labels/BRACS_synthetic.csv`) + the fold's real early-stopping slides (Validation) and `bags` = `ChainBags(SyntheticBags, real bags)`; held-out slides and Testing stay real (`fold_data`/`cross_validate` unchanged). The number of clusters `syn_k` (`K_VALUES`) is searched (`SPACE = {**DEFAULT_SPACE, 'syn_k': ...}`, `synthetic_objective_factory`, `setting_with_k`, `synthetic_cross_validate`). `SCORING`: `'cv'` (pooled out-of-fold, optimistic because the generator saw all official Training slides) or `'validation'` (`validation_mask`: held-out official Validation slides of patients without Training slides; few slides). Study `three_class_syn_pca<DIMENSION>_<SCORING>` in `outputs/02_4_tuning/`, ensemble `classifier/final/noncancer_noninvasive_invasive_synpca<DIMENSION>/`. Section 8 builds the compared-results table (`views`, `summary_across_sets`, paired bootstrap, synthetic-trained minus other) against the 02_3 PCA ensemble, the 02_1 model and the 02_2 ensemble; each is skipped when its file is missing. Class balance of the synthetic set is set by 01_3 (same bags per BRACS class); the scaler is fitted on the synthetic bags.
- `03_reidentification_risk_assessment.ipynb`: planned, empty. When a notebook is created or changed, update its Mermaid diagram in `README.md` (diagrams are in notebook order).

## Code style (match the existing files)

- Section banners: `# IMPORTS ****...`, `# Internal imports ****...`, `# Main function ****...`, each 100 columns wide.
- Inside functions, number the logic with `# STEP n: ...` comments.
- Docstrings list parameters under `* Arguments:` as `name: description`.
- Type hints use modern syntax (`str | None`). Prefer small private helpers with a leading underscore.
- Plot functions take `show: bool = True`, return the figure (or a dict containing it), and style themselves with `plt.rc_context` so global matplotlib settings are untouched.
- Charts use the validated dataviz palette (categorical blue/orange/aqua, blue sequential ramp, blue-orange diverging for residuals); the first 3 categorical colours are colour-blind-safe in scatter and map plots. `plot_cls_overview` accepts any `n_clusters`, with extra non-validated colours beyond 3 (the user's choice).
- **Captions and notebook text are written for a PhD thesis**: concise academic prose that states what is plotted in statistical terms, how to interpret it, and the caveat or consequence. No "what / how to read" or "good / warning" labels, no informal rules of thumb without a source. Separate paragraphs with a blank line. Cite the standard reference when a measure has one (silhouette: Rousseeuw 1987; Davies-Bouldin 1979; adjusted Rand index: Hubert and Arabie 1985; class-balanced loss: Cui et al. 2019). Do not state results in a caption that depend on the data unless they are computed into it.

## Gotchas

- **Slide order matters.** `generate_features` writes a slide's file when the next slide starts, so the loader must use `shuffle=False` and tiles must stay slide-major. DataLoader workers keep batch order, so `num_workers > 0` is fine.
- **Pickling.** Python 3.14 uses `forkserver`, so the dataset is pickled for worker processes. `WSITileDataset.__getstate__` drops the cached pyvips image. The `tile_filter` must be picklable (a `functools.partial` of a module-level function works, a lambda does not) whenever `index_workers > 1`.
- **Pyramid levels.** Level 1 is full resolution; higher is more downsampled. 12 of the 547 slides have only 3 levels (skipped at level 4), and the downsample of level 4 is 32x or 64x depending on the slide. Tile counts grow about 16x per level step toward level 1; a full-resolution level cannot be loaded as one array (read regions lazily, see `plot_pyramid._read_region`).
- **Damaged data.** Some SVS files have unreadable JPEG tiles (for example `BRACS_1791.svs` at level 2). Indexing skips those tiles when a tile filter is set and records them in `dataset.unreadable_tiles`.
- **Output size.** Patch tokens are about 99% of a feature file. Default to `save_patch_features=False` unless patch-level work is planned.
- **Old feature files** may lack `tile_params`; the inspection code handles that.
- **Official split.** The BRACS Testing set is used unchanged and only once (comparability with published work). In notebook 02 the official Training and Validation slides are pooled and re-split into patient-grouped, class-stratified folds for every choice (the official Validation set alone is too small and noisy); other notebooks may still use the official three-way split. Known caveats, all reported by notebook 00: patient 67 has slides in Training and Validation; 78 of 189 patients have slides of several classes; Validation and Testing classes are small. Group by patient in any cross-validation inside Training; never split by tile.
- **Labels are weak.** A slide label is its highest-grade RoI and describes the tissue, not the person. Tile labels inherited from the slide are noisy.
- **Class weights come from the Training set only.** Evaluate with unweighted balanced accuracy and per-class recall on untouched Validation/Testing. `class_analysis` uses the same `compute_class_weights`.
- **Test-set discipline (notebook 02).** `train_model` is given labels of its fit and early-stopping slides only (labels of slides marked `Testing` are not even available inside it); `mil_cv.make_cv_folds` relabels the held-out fold of each cross-validation fold as `Testing` inside the fold table and leaves the real Testing slides out of every fold, so held-out labels are never used for fitting or stopping. Loss weighting (5.1), regularisation (dropout, weight decay, tile dropout; 5.2), the coarse auxiliary loss (5.3) and the epoch (early stopping on the macro-F1 of the early-stopping slides, patience counted after the warm-up) are chosen by cross-validation; class weights come from the fit slides of each fold. The real Testing set is first used in section 6 and nothing is changed afterwards. Keep it that way in any new code.
- **Seed and device.** One `SEED` (`mil_train.set_seed`) drives every random choice; run i of a model uses `SEED + i`. Code is device-agnostic: the device comes from `utils.device.get_device()`, there are no `.cuda()` calls, and bf16 autocast is enabled only when `device.type == "cuda"`. This machine has no GPU and no feature files (they are on the workstation): test with synthetic features that carry real BRACS slide names (as done in the session scratchpad) on the CPU, and say that the GPU path was not run here.
- **Possible batch effect.** Scan year is associated with class (Cramer's V about 0.27) and two MPP values exist (0.2519, 0.2524); check this before interpreting classifier results.
- **Dependencies.** scikit-learn (and its dependency scipy) was added with the user's approval for the classification metrics of notebook 02 (`classification_metrics.py`); the earlier analyses (permutation tests, own k-means, ARI, NMI, silhouette) stay in numpy/torch. optuna was added with the user's approval for the hyperparameter search of notebook 02_2; seaborn and openpyxl are not installed; do not add any other package without asking. The xlsx is parsed with the standard library.
- Data and features live on a remote workstation (`/mnt/Data/bracs/data`, `/mnt/Scratch/phd_streamembed_features`); paths in the notebooks may not exist on this machine (locally the slides are in `data/`), so confirm the host before assuming a file is missing.
- Editing a notebook: it is edited on disk as JSON (keep `indent=1`, `ensure_ascii=False`, new cells need an `id`). Warn the user to reload it in Jupyter so an open copy does not overwrite the edit. Clear the outputs of cells whose code changed.
- `utils/__pycache__/*.pyc` files show up in `git status` (no `__pycache__` entry in `.gitignore`); do not add them to commits.
- `todo_list.py` is the user's plain list of TODO comments, not code to run.
